# 常见问题

## 转换效果

### 转换后文件比原来还大？

正常。常见原因有三个：

1. **目标格式本身更"重"**。把已经压好的 H.264 转成 ProRes 或 MJPEG，
   体积会涨几倍到几十倍——那是专业剪辑用的中间格式，不是用来省空间的。
2. **PNG / TIFF 是无损格式**。JPEG 转 PNG 通常会让文件变大 5～10 倍，
   因为 PNG 不做有损压缩。
3. **画质档位选高了**。想变小就把画质调到「小体积」或「极小体积」。

想真正省空间：JPEG → WebP 通常减小 25%~35%；视频用 H.265 / VP9 / AV1
比 H.264 小约 40%。

### 转出来的视频在手机上放不了？

选 **MP4 / H.264（兼容性最好）**。这是所有设备都支持的组合。

H.265、VP9、AV1 体积更小，但老设备可能没有对应的解码器。
另外 MKV、AVI、FLV 这些容器本身在手机上支持得就不好。

### 视频转 GIF 之后文件特别大？

GIF 格式本身只支持 256 色且不做帧间压缩，体积天然很大。建议：

```
MediaConv.exe convert 视频.mp4 -t gif_anim --fps 12 --scale 480
```

帧率降到 10~15、分辨率降到 480p 以下会好很多。如果只是要发聊天软件，
WebP 动图能小好几倍，画质还更好。

### HEIC 照片转不了？

程序已内置 HEIC 支持（pillow-heif 插件），正常情况下可以直接转。
如果提示不支持，可能是：

- 杀毒软件把 `_internal` 下的 `_heif` 相关文件删了 → 重新解压/安装
- 用了免安装版但没解压完整 → 重新完整解压

用 `MediaConv.exe info` 可以看到 `HEIC : 支持` 或 `不支持`。

### 能保留 EXIF 拍摄信息吗？

图形界面在「图片」标签页勾选「保留 EXIF 等元数据」，
命令行加 `--keep-metadata`。

注意：转成不支持元数据的格式（如 BMP、QOI）时会被忽略。

## 使用问题

### 双击没反应 / 一闪就没了？

先把程序放到**路径不含特殊字符**的目录（例如 `D:\MediaConv\`），
然后打开命令提示符，用命令行运行看报错：

```
D:\MediaConv\MediaConv.exe info
```

如果命令行能跑，说明是图形界面环境问题（多是缺显卡驱动或 Qt 库被杀软拦截）。

### 提示"找不到 ffmpeg"？

程序目录下的 `_internal\bin\` 里应该有 `ffmpeg.exe` 和 `ffprobe.exe`。

- 被杀毒软件误删 → 恢复或重新安装
- 想用自己的 ffmpeg → 设置环境变量 `MEDIACONV_FFMPEG` 指向它

### 界面上的格式列表比文档里少？

格式列表是**运行时探测本机真实能力**生成的，不会列出转了会失败的格式。

- 视频格式少了 → 当前 ffmpeg 构建没编译对应编码器
- 图片格式少了 → 缺 pillow-heif / pillow-avif 插件

用 `MediaConv.exe info` 能看到详细情况。

### 会覆盖我的原文件吗？

**不会。** 默认输出文件带 `_converted` 后缀，同名时自动加 `_1`、`_2`。

只有主动勾选「允许覆盖同名文件」或加 `--overwrite` 才会覆盖。

### 能批量转几百个文件吗？

可以。程序**顺序**处理（不会同时开一堆任务把电脑卡死），
中途可以点「停止」。

命令行配合 `--json-out` 可以拿到结构化结果：

```
MediaConv.exe convert D:\照片 -t WEBP --json-out 结果.json
```

### Windows 提示"未知发布者"？

程序未做代码签名（代码签名证书需要付费）。exe 属性里的发布者信息是 `xiaoke`。

点「更多信息」→「仍要运行」即可。介意的话可以自己用
`signtool` 加签名。

## 手机版

### 界面拖不动怎么办？

1.0.0 已改用自定义的 `DragScrollView` 显式接管触控。
如果仍然拖不动，请抓一段日志：

```
adb logcat -s DragScrollView
```

拖动时应看到 `drag start: scrollY=0 content=… viewport=…`：

- **有这行但界面不动** → 问题在绘制层，请反馈机型与系统版本
- **完全没有这行** → 手势在到达控件前被拦截了，同样请反馈

### 视频格式只有一两种可选？

手机版的输出格式取决于**你机型的硬件编码器**。
低端机可能只有 H.264 编码器，因此列表里就只有 MP4 · H.264。

界面里有一行「本机可用：…」，显示这台设备实际支持的类型。
这是有意设计——避免让你选了之后转换失败。

### 转码很慢或手机发烫？

转码调用的是硬件编解码器，比纯软件快很多，但仍会占用较多资源。
建议：

- 大文件转到 720p 或 480p
- 转码时不要同时运行大型游戏
- 手机电量低时系统会降频，速度会变慢

### 转换结果保存在哪？

- 视频 → `相册/Movies/MediaConv/`
- 图片 → `相册/Pictures/MediaConv/`
- 音频 → `相册/Music/MediaConv/`

原文件不会被修改或删除。

## 其它

### 有 Mac / Linux 版吗？

暂时没有提供打包产物，但**代码本身是跨平台的**：
路径处理用 `pathlib`，ffmpeg 定位兼容多平台。

理论上在 Mac/Linux 上：

```bash
pip install PySide6-Essentials pillow pillow-heif pillow-avif-plugin
# 把 ffmpeg / ffprobe 放到 desktop/bin/
python desktop/MediaConv.py
```

### 会联网吗？会上传我的文件吗？

**不会。** 程序没有任何网络请求代码，断网可以正常使用。

转换全部在本机完成，文件不会离开你的设备。

### 可以商用吗？

源代码是 MIT 许可，可以商用。

但**分发的二进制包内置 FFmpeg（GPL v3）**，再分发时需遵守 GPL v3。
详见 [THIRD_PARTY_LICENSES.md](../THIRD_PARTY_LICENSES.md)。

### 能加 XX 格式支持吗？

欢迎在 Issue 里提。如果 ffmpeg 支持该格式，通常只需在
`Formats.py` 里加一条定义即可，详见
[贡献指南](../CONTRIBUTING.md#添加新格式支持)。
