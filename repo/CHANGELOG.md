# 更新日志

## [1.0.0] - 2026-10-10

首个正式版本。包含 Windows 电脑版与 Android 手机版。

### 新增

**电脑版**
- 图形界面（PySide6）：文件列表、拖拽添加、格式与画质设置、进度显示
- 命令行界面：`info` / `list` / `convert` / `version` 四个子命令，支持通配符与文件夹批量
- 图片转换 23 种输出格式，含 HEIC、AVIF、APNG、QOI、JPEG 2000 等
- 视频转换 20 种输出组合，覆盖 H.264 / H.265 / VP9 / VP8 / AV1 / ProRes / Theora / MPEG-2
- 音频转换 12 种输出格式，可从视频提取音轨
- 支持时间裁剪（`--trim`）、分辨率缩放、帧率调整、仅换容器不重编码（`--copy`）
- 内置完整版 FFmpeg 与 ffprobe，开箱即用，无需额外安装

**手机版**
- 图片转换：读 HEIC / JPEG / PNG / WebP / GIF / BMP / TIFF / AVIF，写 JPEG / PNG / WebP（含无损）
- 视频转码：基于 `MediaCodec` 硬件编解码，输出 MP4（H.264 / H.265）与 WebM（VP8 / VP9）
- 音频提取：可直接输出 M4A / AAC
- 输出格式按机型实际支持的编码器动态生成，不支持的不会出现
- 支持从相册「打开方式」与分享菜单直接进入

### 修复

以下问题都是在开发过程中实际发现并修复的，记录在此以便追溯：

- **给没有音轨的视频提取音频时提示无法理解**
  之前直接抛出 ffmpeg 的 `Error opening output files: Invalid argument`。
  自造测试样本恰好都有音轨，所以一直没暴露；改用公网真实素材测试后才触发。
  现在会提前检查流，提示「这个文件没有音轨，无法提取音频……请选择视频格式」。
  反向情况（纯音频转视频容器）同样有明确提示。

- **音频目标的参数冲突导致转换失败**
  音频容器同时被加上了 `-vn` 与 `-an`，ffmpeg 认为没有任何流要输出而报错。

- **`-movflags +faststart` 被错误地加到 MP3 等容器上**
  导致「Error opening output file ... Invalid argument」。
  该参数只对 mov / mp4 / ipod 系列有意义。

- **双击或从快捷方式启动时会闪出 cmd 黑窗口**
  原因是打包时用了 `console=True`，exe 被编译成控制台子系统。
  改为 GUI 子系统（`Subsystem=2`）后 Windows 从根上不创建控制台；
  命令行模式改为主动附加父进程控制台，并优先复用继承的标准句柄，
  以免管道调用（`MediaConv.exe info | more`）收不到输出。

- **图片格式列表只剩 2 项**
  Pillow 的格式插件是惰性导入的，未导入前 `Image.SAVE` 几乎是空的。
  改为显式调用 `Image.init()` 后再判断可写格式。

- **HEIC / AVIF 支持未生效**
  可选插件没有被注册，导致格式列表里缺项、转换报错。改为在模块导入时统一注册。

- **首次启动时 HEIC 插件加载失败**
  wheel 解包后 `.data/platlib` 目录未展开，原生库不在预期位置。

- **手机版界面无法上下滑动**
  原生 `ScrollView` 的触控拦截依赖内部状态，在"纯代码构建视图"的路径上不可靠。
  改为自定义 `DragScrollView` 显式接管触控：超过 touchSlop 即接管，
  抬手后交给 `Scroller` 做惯性滑动。

- **手机版视频格式只有一个选项**
  输出格式原本写死为 MP4/H.264。改为启动时查询 `MediaCodecList`，
  列出本机真实支持的组合。

- **手机版音频时间戳可能回退**
  直接沿用解码器的 PTS，seek 之后可能变小，会让 `MediaMuxer` 报错。改为单调递增自算。

- **手机版纯音频目标失败时会留下空文件**
  现在明确报错并清理。
